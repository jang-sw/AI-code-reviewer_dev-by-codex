## 1. 적용 범위

- 여러 단계가 필요한 기능 구현, 버그 수정, 중단된 개발 재개에 사용한다.
- 기존 프로젝트의 수정·확장과 신규 프로젝트 개발에 모두 사용할 수 있다.
- 단순 설명·읽기 전용 리뷰·한 줄 문구 수정에 전체 절차를 강제하지 않는다.
- 작업 범위와 권한은 사용자 요청, 적용되는 작업 지침, 실행 환경의 보호 정책을 따른다. 스킬 사용만으로 외부 변경 권한이 생기지는 않는다.

## 2. 작업 시작

1. 적용되는 `AGENTS.md`와 이번 요청을 확인한다. 참고 문서 설정에 따라 `PROJECT.md` 또는 기존 README에서 관련 부분만 읽는다.
2. 기존 코드가 있으면 현재 구조·관련 기능·테스트·실행 방법부터 확인한다. 없는 신규 코드를 이미 구현된 것처럼 가정하지 않는다.
3. Git 상태와 기존 사용자 변경을 확인한다. 상태 기록이 켜져 있으면 `WORK.md`도 확인하고 실제 코드와 맞는지 대조한다. Git 미사용이면 Git 확인은 생략한다.
4. 이번 작업의 완료 조건과 변경 범위를 정한다. 큰 작업만 검증 가능한 작은 단위로 나누고, 상태 생성·갱신은 `AGENTS.md`의 설정을 따른다.

## 3. 구현과 검증

1. 기존 프로젝트에서는 관련된 최소 변경을 수행하고 요청과 무관한 언어·구조·호환성을 바꾸지 않는다. 신규 프로젝트는 확정한 범위와 기술로 구현한다.
2. 변경에 관련된 정상·오류·경계 조건을 확인하고 테스트를 추가·수정한다.
3. 검증 명령의 실행 대상과 부작용을 확인한 뒤 안전한 개발·테스트 환경에서 실행한다.
4. 기존 실패와 새 실패, 실제 통과와 미검증을 구분한다. 테스트가 없거나 실행할 수 없으면 이유와 가능한 대체 검증을 남긴다.
5. 변경 내용을 다시 검토하고, 단계 완료 또는 막힘 시 설정에 따라 작업 상태를 갱신한다.

## 4. 마무리와 다음 작업

1. 사용자가 승인한 경우에만 `AGENTS.md`의 Git 정책에 따라 작은 작업 단위마다 커밋·푸시한다. 스킬 자체에서 별도 승인이나 업로드 대상을 추정하지 않는다.
2. 상태 기록이 켜져 있으면 최종 응답 전 완료한 부분·다음 할 일·미검증 사항을 정리한다. 상태 파일만을 위한 반복 커밋은 만들지 않는다.
3. 변경 내용·실제 검증 결과·남은 문제를 보고한다. 커밋·푸시했다면 실제 결과를 별도로 보고한다.
4. 다음 작업을 재개할 때 기록만 믿지 말고 현재 코드와 변경 상태를 확인한 후 이어간다.
