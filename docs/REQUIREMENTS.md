# AI 소스코드 리뷰 시스템 요구사항

## 확정된 목표

실제 운영 가능한 AI 소스코드 리뷰 서비스를 개발한다. MVP 구현만으로 완료 선언하지 않는다. 기획, 구현, 자동 테스트, 실제 실행 검증, 운영·보안 검증과 릴리스 준비를 수행한다.

사용자 요청 기준: 2026-09-25. 기존 PROJECT.md 기술 제약을 함께 적용한다.

## 기능

1. GitHub와 설치형 GitLab을 지원한다. 프로젝트 ID를 입력받지 않고 HTTP(S) 저장소 링크를 clone처럼 입력한다. `.git` 접미사를 처리하고 중첩 GitLab 그룹을 지원한다. 비공개 저장소 인증은 서버의 안전한 설정으로 관리하며 URL에 토큰을 넣지 않는다.
2. 승인된 등록 프로젝트를 1시간마다 리뷰한다. 사용자 확정: **최초 실행은 전체 이력**을 오래된 커밋부터 처리한다. 큰 이력은 배치로 나누고 이후 새 커밋을 이어서 처리한다. 실패한 커밋을 누락하거나 중복 이슈를 생성하지 않는다.
3. AI는 로컬 Ollama 직접 연결, LiteLLM, **OpenAI API 직접 연결**을 제공한다(2026-09-26 추가). properties/환경변수로 공급자, 주소, 모델, 인증, 시간 제한을 설정한다. API 키는 서버 환경변수/비밀 설정으로만 주입하며 코드·Git·브라우저·로그에 넣지 않는다. 기존 문서의 Gemma3.1b는 Ollama 모델 태그 `gemma3:1b`를 기본값으로 해석하며 실제 설치 모델과 품질을 검증한다.
4. ADMIN과 USER 역할을 제공한다. **누구나 회원가입을 신청하고 관리자가 승인한다**(2026-09-26 정정). 계정 정보는 ID, 비밀번호, Git 계정이다. 일반 가입에서 관리자 역할을 선택할 수 없으며 승인 전 이용을 제한한다. 초기 관리자만 별도 bootstrap 설정으로 생성한다. ADMIN은 가입과 프로젝트 생성 요청을 승인·반려하고 계정을 관리한다. 비밀번호 원문은 보관하지 않는다.
5. USER는 프로젝트 등록을 요청하고 자신의 프로젝트·리뷰와 자신에게 배정된 이슈를 확인한다. 승인 전·일시정지 프로젝트는 자동 리뷰하지 않는다.
6. 사용자 확정: **시스템 내부 이슈함 우선**. AI의 수정 권고를 커밋 작성자의 Git 계정과 연결한 사용자에게 배정한다. Git 작성자 식별 또는 계정 매핑 실패 시 프로젝트 소유자에게 배정하고 이 사유를 표시한다. 외부 GitHub/GitLab 이슈 등록은 이후 선택 기능이며 현재 자동 작성하지 않는다.
7. 이슈는 심각도, 파일·행, 문제 설명, 수정 제안, 관련 커밋을 보관하고 OPEN/RESOLVED/DISMISSED 상태로 관리한다. AI 결과는 권고이며 자동 코드 수정·푸시하지 않는다.
8. 관리자 승인, 계정 변경, 리뷰 실행, 이슈 상태 변경은 감사 기록을 남긴다.
9. 사용자·프로젝트·리뷰·이슈 등 누적되는 목록은 조회량을 제한하고 필요한 페이지 탐색/검색·필터를 제공한다(2026-09-26 추가). 페이지가 바뀌어도 권한 범위와 검색 조건을 유지한다.
10. 화면은 가입 신청 → 승인 대기 → 프로젝트 등록 → 프로젝트 승인 → 리뷰 확인 → 내 이슈 처리라는 사용자 흐름으로 설계한다(2026-09-26 추가). 내부 코드/영문 상태값 대신 이해하기 쉬운 상태·다음 행동, 빈 화면 안내, 오류 복구와 모바일/키보드 사용성을 제공한다.
11. 바이너리·모델 입력 한도 등 AI가 검토하지 못한 변경은 **수동 확인 이슈를 배정하고 다음 커밋으로 진행한다**(2026-09-26 확정). AI 결함 권고와 별도로 표시하고, 확인 가능한 전체 변경 경로와 근거를 보존한다. 변경 범위의 완전성을 증명할 수 없거나 API·응답 검증 오류가 있으면 중단한다.
12. 운영 AI의 연결·모델 품질 검증은 **LiteLLM을 우선**한다(2026-09-27 확정). Ollama와 OpenAI 직접 연결 지원도 유지한다. 연결 성공과 리뷰 내용의 품질 합격은 구분한다.
    현재 LiteLLM 프록시 주소·모델은 정해지지 않아 설정·검증 도구부터 준비한다. 실제 연결과 모델 품질은 대상이 준비된 뒤 별도로 검증한다.

## 기술 제약

- Java 25, Spring Boot, Maven, PostgreSQL, JSP + JSTL.
- 애플리케이션은 `source/` 아래 Spring 표준 디렉터리로 구성한다.
- JSP에 Java scriptlet을 넣지 않는다. 동적 출력은 이스케이프한다.
- JSP 지원을 위해 실행 가능한 WAR로 패키징한다.
- 데이터베이스 버전 관리는 Flyway SQL 마이그레이션을 사용한다.
- 운영 대상은 **Linux 서버, Docker 미사용**이다(2026-09-26 확정). Java 실행 WAR와 systemd 기반 실행·업데이트·백업·롤백 절차를 준비한다.
- 2026-09-30 사용자는 **WSL을 구축해 Linux 환경 검증을 진행**하도록 요청했다. Windows 소스/기존 PostgreSQL 데이터와 분리한 WSL2 Linux 환경에서 Docker 없이 설치·실행·복구를 확인한다. WSL 검증 결과와 별도 운영 서버의 TLS·재부팅·자원/보안 검증 범위는 구분한다.

## 운영 품질·완료 조건

- 인증, 역할·소유권 검사, CSRF, 비밀번호 해시, 세션 만료/폐기, 입력 검증과 비밀정보 보호.
- Git API 페이지 처리, API 제한·시간 초과·잘못된 자격증명, force-push, 빈 저장소, 큰 커밋·바이너리·다중 브랜치/병합을 명시적으로 처리. 누락을 성공으로 기록하지 않는다.
- 시간별 작업 중복 실행 방지, 재시작·재시도, 커밋 단위 원자성, 이슈 중복 방지, 진행·실패 상태 표시.
  구현 정책으로 외부429는 요청·저장 결과를 보존하여 최대5회/24시간 대기하고, 상한 초과 후 서비스 확인과 직접 재접수를 안내한다. origin별 서버 공유와 세부 제한은 `EXTERNAL-RATE-LIMITS.md`를 따른다.
- AI 응답 스키마 검증, 응답 크기·시간 제한, 프롬프트 주입 방어, 코드/토큰 로그 노출 방지. 로컬 모델의 유효한 JSON 출력과 리뷰 품질을 실제 검증.
- 단위·권한·통합·실제 PostgreSQL·패키지 실행·화면·접근성·반응형 검증. 외부 GitHub/GitLab/Ollama/LiteLLM 실제 연결, 대형 저장소와 장애 복구, 부하 검증.
- 운영 설정, HTTPS/프록시, 백업/복원 실증, 모니터링, 보존 정책, 업그레이드/롤백, 설치·사용 가이드, 의존성 취약점 검사와 릴리스 체크리스트.
- 모든 필수 구현과 테스트가 충족되고 릴리스 가능한 상태에서만 사용자에게 **완료**라고 보고한다. 미검증 항목을 통과로 적지 않는다.

## 작업·재개 방식

- 한 회차는 최대 약 2시간. 장기 실행을 무기한 이어가지 않고 검증 결과와 다음 작업을 남긴다.
- 사용자가 `이어서 진행`이라고 하면 AGENTS.md, 이 문서, PROJECT.md, WORK.md와 실제 Git 상태를 먼저 대조하고 미완료 작업을 이어간다.
- 요구 변경은 이 문서에, 실제 구현/실행 방법은 PROJECT.md, 최신 상태/재개 항목은 WORK.md에 갱신한다.
- 검증 가능한 작은 단위로 변경 검토 → 테스트 → 로컬 커밋한다. 기존 사용자 변경은 보존한다.
- main 직접 푸시, 운영 배포, 실제 데이터 삭제, 유료 자원 변경, 외부 메시지/이슈 작성은 별도 승인이 필요한 작업이다. 현재 요청은 개발·테스트와 중간 로컬 커밋을 승인한다.

## 남은 제품 결정

- 계정 셀프 가입과 관리자 승인은2026-09-26 사용자 요청으로 확정했다. 기존 관리자 직접 생성 화면은 가입 승인 화면으로 전환한다.
- 관리자 origin/작성자 이메일 매핑과 호스트별 복수 자격증명은 구현했다. 프로젝트 팀 멤버십·사용자별 여러 Git 계정·외부 이슈 동기화는 별도 범위 결정이 필요하다.
- 기본 브랜치 전체 이력을 우선하며, 모든 브랜치 리뷰는 별도 정책과 중복 처리 기준이 필요하다.
- Linux 비Docker 운영 대상으로 확정했다. 실제 배포 서버 접근과 운영 배포 승인은 아직 제공되지 않았다.
