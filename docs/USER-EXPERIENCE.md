# 사용자 흐름과 화면 기준

사용자가 해야 할 일을 기준으로 메뉴와 화면을 구성한다. 구현한 동작과 아직 남은 검증을 구분하며, 최신 검증 결과는 WORK.md에 기록한다.

## 가입부터 첫 리뷰까지

1. 로그인 화면에서 회원가입으로 이동한다. ID·Git 사용자명·비밀번호·확인을 입력하고 가입 승인을 요청한다. 가입 접수 화면은 관리자 승인 후 로그인할 수 있음을 안내한다. 중복 가입 여부는 공개하지 않는다.
2. 관리자는 관리자 메뉴의 가입 승인에서 대기 요청을 확인한다. 승인·반려·반려 요청 재검토를 할 수 있다. 승인된 사용자의 이용 중지와 비밀번호 초기화는 사용자 관리에서 수행한다.
3. 승인된 사용자는 프로젝트에서 저장소 URL을 붙여 넣는다. 이름과 브랜치는 선택 정보이며 기본값을 사용할 수 있다. 필드별 오류와 입력값을 유지하되 자격증명이 포함된 URL은 다시 표시하지 않는다.
4. 프로젝트 상세는 현재 승인 상태와 다음 행동을 안내한다. 관리자 승인 후 매시간 리뷰하거나 지금 리뷰를 실행한다. 전체 이력을 여러 번에 나누어 처리하므로 실행 한 번의 완료와 전체 과거 이력 검토 완료를 구분한다.
   현재 요청 카드에는 마지막 처리 단계, 이번 시도에서 새로 저장한 커밋 수, 마지막 저장 시각을 표시한다. 화면을 새로고침해 기록을 확인하고 이전 시도의 저장 결과는 재사용한다. 수동 확인 배정도 포함되므로 담당자의 확인 완료 건수와 구분한다.
5. 이슈 목록에서 심각도·상태·파일·짧은 설명을 비교하고 상세에서 전체 권고와 배정 근거를 읽는다. 원본 커밋은 새 창으로 열린다. 코드를 확인한 뒤 해결·검토 제외·미처리 상태를 저장한다.
6. Git 이력이 재작성되어 리뷰가 멈추면 관리자가 프로젝트를 일시 중지하고 복구 영역에서 주소·사유를 확인한다. 기존 리뷰와 이슈는 보존하며 자동 재개하지 않는다. 복구 실패 화면은 구체적인 다음 행동과 프로젝트 복귀 링크를 제공한다.

## 정보 구조와 부하

| 화면 | 기본 상태와 조회 범위 | 다음 행동 |
|---|---|---|
| 홈 | 본인 프로젝트·담당 이슈 요약, 관리자는 전체 | 이슈 확인, 프로젝트 등록, 승인 요청 확인 |
| 프로젝트 | 이름/URL 검색, 승인 상태, 50건 | 상세와 리뷰 기록, 등록 |
| 사용자 | 승인 대기 기본, ID 검색과 승인 상태, 50명 | 승인 또는 계정 관리 |
| 이슈 | 미처리 기본, 상태 필터, 25건/설명240자 | 상세 권고 읽기, 상태 저장 |
| 리뷰 기록 | 실행/커밋 독립 50건 | 실패 원인과 검토 범위, 재실행 |
| 감사/작성자 매핑 | 관리자만, 50건 | 운영 변경 확인/작성자 연결 |
| 서버 상태 | 관리자만, 주기적으로 수집한 캐시 요약 | 관측 최신성 확인, 실패·지연 운영 목록으로 이동 |

페이지는 0..10000으로 제한한다. UI는 1부터 표시하고 조회 조건을 페이지 링크에 유지한다. 전체 건수를 매번 세지 않고 한 건을 더 조회해 다음 페이지를 판단한다. 이슈 상세도 담당자와 관리자 권한을 다시 검사한다.

## 호출 제한과 리뷰 기록 읽기

외부 Git 서버나 AI 서비스가 호출을 제한하면 최근 요청 카드에 제한된 서비스와 UTC 재시도 가능 시각을 표시한다. 요청과 이미 저장된 리뷰·이슈는 유지하며, 대기 중에는 중복 요청 버튼을 비활성화한다. 해당 시각은 완료 예정 시각이 아니다. 자동 재시도 상한에 도달하면 직접 다시 요청해야 한다는 안내와 버튼을 제공한다. 관리자는 운영 현황의 ‘외부 서비스 호출 제한 대기’ 필터로 해당 요청만 확인할 수 있다.

리뷰 기록의 실행 시작·종료와 커밋 검토 시각은 서버 시간대에 관계없이 UTC 초 단위로 표시한다. 각 값에 UTC를 명시하고 HTML `time`의 `datetime`에는 원래 시각의 정밀도를 유지한다. 종료 시각이 없는 실행에 임의의 종료 시각을 넣지 않는다. 최근 요청 카드의 UTC 시각과 같은 기준으로 비교한다.

## 관리자 서버 상태 확인

관리자 메뉴의 **서버 상태**에서 마지막 성공 관측 시각과 수집 상태를 먼저 읽는다. 첫 수집 대기·수집 실패·오래된 관측은 수치를 숨기고 확인 불가를 안내하며, 과거 수치를 정상0건으로 보여주지 않는다. 사용 가능한 관측에서만 승인 프로젝트·대기 요청·처리 중으로 기록된 요청 수치와 실패·지연 화면 알림을 제공한다.

실패 알림은 최근 실행 실패 목록으로, 지연 알림은 원래 접수 후 오래 미완료인 요청 목록으로 이동한다. 처리 중 기록은 실제 작업자가 살아 있음을 보장하지 않으며 접수 후 경과에는 재시작 복구 시간이 포함될 수 있음을 설명한다. 화면 새로고침은 캐시를 다시 읽는 동작이고 즉시 재집계하거나 리뷰를 실행하지 않는다.

집계는 연결된 DB 전체를 대상으로 하되 관측 캐시와 worker·새 예약 생성 설정은 현재 서버의 값임을 구분한다. 다른 서버의 처리가 계속될 수 있음을 안내한다. 알림은 이 화면에만 표시하고 이메일·푸시로 발송하지 않는다. 화면과 JSON 모두 현재 승인·활성 관리자 권한을 재검사한다. 시각은 UTC 초 단위로 읽기 쉽게 표시하고 원본 시각은 HTML datetime과 JSON에 유지한다. 수집·지표·접근 정책의 상세 계약은 [모니터링 가이드](MONITORING.md)를 따른다. 실제 화면 검증 결과는 WORK.md에서 확인한다.

## 화면 점검 기준

- 한국어 승인/처리 상태, 빈 목록의 이유와 다음 행동, 오류 안내를 제공한다.
- 로그인 없이 볼 수 있는 메뉴와 사용자/관리자 메뉴를 구분한다.
- 키보드 포커스, label 연결, 본문 건너뛰기, CSRF, 출력 escaping을 유지한다.
- 모바일 화면에서 페이지 자체가 가로로 넘치지 않아야 한다. 긴 표는 별도 스크롤 영역과 키보드 안내를 제공한다.
- 가입 오류, 승인 전 로그인, 가입 승인, 프로젝트 등록/승인, 목록 필터/페이지, 이슈 상세/상태 저장을 실제 WAR에서 확인한다.

이 문서는 사용자 인수 승인을 대신하지 않는다. 이메일 알림, 실시간 진행 알림, 운영자의 반려 사유를 사용자에게 전달하는 별도 채널은 현재 구현 범위 밖이다.
