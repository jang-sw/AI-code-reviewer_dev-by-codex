# 화면 인수 조건과 재개 순서

전체 화면 인수의 누락과 반복을 줄이기 위한 검증 계획이다. 새 제품 요구사항을 추가하거나 기존 HTTP·DB 회귀를 브라우저 인수로 바꾸지 않는다. 전체 인수와 사용자 승인은 아직 미완료이며 [릴리스 기준](RELEASE-CHECKLIST.md)을 유지한다.

## 증거를 판정하는 방법

- 화면 종류마다390px·1280px에서 제목·메뉴·도움말·본문 가로 넘침을 확인한다. 긴 표는 별도 영역에서 키보드로 이동하고 포커스가 보여야 한다.
- 각 상태 분기의 행동은 아래 표의 대표 크기에서 Tab/Shift+Tab·Enter/Space로 수행한다. 각 오류의 필드 링크, 저장 여부, 복귀 경로를 확인한다. 모든 상태와 크기를 곱해 검증했다고 보고하지 않는다.
- 변경 전후의 실제 DB 기대값과 감사 건수를 대조한다. 조회만 하면 업무·기존 감사가 그대로여야 하고, 거절된 요청으로 변경이 발생하면 실패다.
- 근거에는 역할, 초기 상태, 크기, 키보드 행동, 관찰한 화면/HTTP, DB 변화, WAR SHA와 증거 경로를 남긴다. 화면 로딩, HTTP/DB 검증, 실제 브라우저 조작을 구분한다.
- 합성 계정·격리 DB·합성 Git/AI만 사용한다. 새 비밀번호의 브라우저 입력·변경은 별도 수동 인수로 남기고 자동 HTTP 회귀와 혼동하지 않는다. 비밀번호·쿠키·CSRF·실제 사용자 행은 공개 증거에 저장하지 않는다.
- 기존 증거의 역할·상태·행동·크기와 코드 변경 범위를 대조해 재사용한다. 관련 코드가 바뀌거나 근거가 부족한 조건만 다시 실행하며 통과한30분 유휴 시험을 이유 없이 반복하지 않는다.

## 조건별 근거와 남은 확인

미완료로 남긴 조건은 미실행이다. 검증한 조건은 해당 행에 통과 범위와 근거를 명시하며, 기존 부분 근거가 있다는 이유로 행 전체를 완료 처리하지 않는다. 세부 동작은 [사용자 흐름](USER-EXPERIENCE.md), 과거 실행의 WAR·증거는 [작업 기록](../WORK.md)을 따른다.
